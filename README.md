# Spendly

1日ごとの出費合計とカテゴリ別の内訳、月ごとの固定費を記録・集計する個人用の家計簿アプリです。Next.js / React / TypeScript / Tailwind CSS / Prisma / PostgreSQL を使用しています。

## できること

- 1日の出費合計を先に記録し、その日のカテゴリ・金額・メモを複数行で管理
- 合計と内訳が一致していなくても保存し、差額を表示
- 月ごとの固定費を日々の支出とは別に記録
- 月の総額を「日々の支出」と「固定費」に分けて表示
- 入力済み内訳のカテゴリ別円グラフ・棒グラフ
- 月・カテゴリ・メモによる日別記録の絞り込み
- カテゴリの追加、名前変更、削除。使用中のカテゴリは削除を防止
- 生活費の月間予算、残り予算、今日を含む1日あたりの目安（固定費とカテゴリ別予算から独立）
- 月締め・振り返りメモ。入力漏れと内訳の差額を確認して翌月から締められ、締めた後の記録変更を検知
- ほしいものリスト。予定金額・商品URL・メモの編集、購入済み管理、購入時の支出登録
- スマートフォン用ナビゲーション、入力エラー表示、読み込み・空状態・404・エラー画面

日付の保存・集計は日本時間（JST）を基準にしています。1日の合計は0円以上、各内訳は1円以上、上限は2,147,483,647円です。

## ローカル起動

Node.js 22 以上と PostgreSQL（Neon など）が必要です。

```sh
npm ci
cp .env.example .env
```

`.env` の `DATABASE_URL`（アプリ用）と `DIRECT_URL`（マイグレーション用）を設定します。Neon ではアプリ用に pooled 接続、マイグレーション用に direct 接続を設定できます。

```sh
npx prisma generate
npm run db:deploy
npm run db:seed
npm run dev
```

[http://localhost:3000](http://localhost:3000) を開いてください。初期カテゴリの投入は再実行可能です。サンプル支出は `npm run db:seed:demo` で追加できます（通常利用のデータベースでは不要です）。

## 検証と本番ビルド

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

GitHub Actions でも lint・型チェック・テスト・ビルドを実行します。ユニットテストは日付境界、金額上限、入力検証を確認し、データベースを変更しません。

Vercel の build はデータベースを変更しません。Production と Preview の環境変数に、アプリ用の `DATABASE_URL` とマイグレーション用の `DIRECT_URL` を登録してください。今後スキーマを変更する場合は、対象のデータベースを確認してから `npm run db:deploy` を別途実行してください。

## 運用範囲

単一ユーザーが localhost で使う構成です。標準の起動コマンドは `127.0.0.1` に限定して待ち受けます。ログイン機能・ユーザー間のデータ分離は実装していないため、一般公開する場合は認証・アクセス制御を追加してください。

接続情報を含む `.env`、ローカルキャッシュ、データベースの内容は Git 管理から除外します。リポジトリから再現するときは、自分のデータベース接続情報を設定してください。

## 月間計画・ほしいもの

- **生活費予算**：月間予算画面で設定します。空欄は未設定、0円も有効です。日々の支出の「1日の合計」を差し引くため、内訳が未完成でも計算できます。固定費は除き、未来の日付の記録は予約済みの出費として差し引きます。過去月の1日あたりの目安は表示しません。未入力の日があれば注意を表示します。
- **月締め**：サイドバー、ダッシュボード、または設定から開きます。メモはいつでも保存でき、月締めは翌月から可能です。未入力・差額があっても確認にチェックすれば締められます。月締めは確認済みの印であり、編集ロックではありません。締めた後に収支・内訳・予算が変わると再確認を促します。「月締めを解除」してから再度締められます。
- **ほしいもの**：予定金額は家計簿に計上しません。「購入して支出に記録」で実際の購入金額・日付・カテゴリを確認し、既存の日の合計と内訳に追加します。購入登録は一度だけ可能です。すでに家計簿へ入力済みの場合は「購入済みにする（支出追加なし）」を使います。ほしいものを削除しても支出記録は残ります。

既存環境では、新しいコードを起動する前に `npm run db:deploy` を実行してください。追加マイグレーションは `MonthlyPlan` と `WishItem` のテーブルを作成し、既存の家計簿データは変更しません。

### データベース統合テスト

破棄可能な PostgreSQL データベースを `TEST_DATABASE_URL` に指定して実行します。

```sh
npm run test:migration
npm run test:planning
```

マイグレーションテストはトランザクションをロールバックします。計画機能テストは独立した一時スキーマに全マイグレーションを適用し、同時購入の二重登録防止、失敗時の巻き戻し、月締め後の変更検知などを検証してスキーマを削除します。GitHub Actionsでも両方を実行します。
